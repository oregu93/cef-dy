# Markdown и LaTeX — правила проекта

## Цель

Минимизировать случаи, когда физические обозначения в Obsidian показываются как код или обычный текст, и сохранить переносимость Markdown между Obsidian, GitHub и VS Code.

## 1. Встроенная математика

Стандарт проекта:

```markdown
CEF-параметр $B_l^m$ и энергия $E_1=18.25~\mathrm{meV}$.
```

Не помещайте математические обозначения в обратные кавычки, если они должны отображаться как формула.

## 2. Отдельные формулы

Используйте отдельный блок с пустой строкой до и после:

```markdown
$$
\hat H_{\mathrm{CEF}}
=
\sum_{l,m} B_l^m \hat O_l^m.
$$
```

## 3. Многострочные формулы

Окружения LaTeX должны находиться внутри математических разделителей:

```markdown
$$
\begin{aligned}
E_1 &= 6.45~\mathrm{meV},\\
E_2 &= 18.20~\mathrm{meV},\\
E_3 &= 27.90~\mathrm{meV}.
\end{aligned}
$$
```

Не используйте standalone `\begin{aligned}` вне `$$...$$`.

## 4. Матрицы

```markdown
$$
U=
\begin{pmatrix}
1 & 0 & 0\\
0 & 0 & -1\\
0 & 1 & 0
\end{pmatrix}.
$$
```

## 5. Формулы внутри списков

Избыточный отступ может превратить display math в code block. Предпочтительный формат:

```markdown
1. Первый пункт.

   Используется соотношение

   $$
   E=\hbar\omega.
   $$

2. Второй пункт.
```

Если конкретная система отображения обрабатывает такой блок нестабильно, вынесите формулу из списка в отдельный абзац.

## 6. Код и математика

Машинные обозначения:

```text
B20, B2n2, instrument_block_id
```

Физические объекты:

$$
B_2^0,\qquad B_2^{-2},\qquad \mathbf Q.
$$

## 7. Единицы

Предпочтительно:

```latex
18.25~\mathrm{meV}
3.5~\mathrm{K}
2.26~\text{\AA}^{-1}
```

## 8. Типографика и устойчивые идентификаторы

Для нового канонического текста предпочтительны `-` или `--`. Новый Unicode
em dash `—` не используется, кроме исторической цитаты, неизменяемого frozen
artifact или дословного внешнего текста. Старый текст не нормализуется массово
только ради типографики.

Формальные устойчивые ID сохраняют точное каноническое написание и регистр,
например:

```text
STAGE03R-INFERENCE-SPEC
STAGE03R-IMPL-REREVIEW-001
W02-02R-B-001
MOD-PCM-M0
```

## 9. Имена файлов

- Существующие канонические пути по умолчанию сохраняются.
- Новый член установленного канонического семейства следует соглашению этого
  семейства.
- Для нового standalone human-facing файла допустим и предпочтителен
  `lowercase-kebab-case`, если нет более сильной семейной конвенции.
- Массовое переименование ради косметической согласованности запрещено.

## 10. Внутренние ссылки

Каноническая навигация использует стандартные относительные Markdown-ссылки.
При первом содержательном упоминании существующего protocol, specification,
checkpoint или register предпочтительна ссылка на файл. В последующих близких
упоминаниях достаточно устойчивого ID.

Stable ID остаётся semantic identity; ссылка служит только навигации. По
умолчанию используются file-level links. Obsidian-only wikilinks не требуются.

## 11. Проверка перед фиксацией в Git

- [ ] Число `$$` чётное.
- [ ] Каждому `\begin{...}` соответствует `\end{...}`.
- [ ] `aligned`, `matrix`, `pmatrix` находятся внутри math blocks.
- [ ] Математика не окружена обратными кавычками по ошибке.
- [ ] Формулы не получили случайный четырёхпробельный отступ.
- [ ] Сложные формулы выборочно проверены в режиме предпросмотра Obsidian.

Автоматическая проверка:

```powershell
python scripts/kb_validate.py
```
