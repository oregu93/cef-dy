# Правила статусов знания

## Типы утверждений

В проекте различаются:

| Type | Назначение |
|---|---|
| `FACT` | Общепринятый или непосредственно проверенный факт, не являющийся спорным проектным выводом. |
| `RESULT` | Результат анализа/расчёта/эксперимента проекта. |
| `HYPOTHESIS` | Проверяемое предположение или assignment. |
| `DECISION` | Принятое правило дальнейшей работы. |
| `OPEN_QUESTION` | Существенный нерешённый вопрос. |

## Запрещённые подмены

- `RESULT` не становится `FACT` из-за низкого loss.
- `DECISION` не является доказательством физической истины.
- `HYPOTHESIS` не следует переписывать как established assignment.
- Отсутствие линии не означает отсутствие уровня без учёта чувствительности и selection rules.
- Совпадение энергий не гарантирует правильность wavefunctions или transition tensors.

## Минимальная provenance discipline

Для каждого существенного численного результата сохранять:

```text
ID
statement
status
scope
evidence
review date
validation criteria
limitations
```

## Superseding

Старый результат не удаляется, если он важен для истории. Он получает `status: superseded` и ссылку на новый ID.
